# 増分2: フィクスチャデータでの判定＋本物の通知内容

## 目的

パイプラインの中身を本物に近づける。静的なフィクスチャデータを入力として、**実質20%以上お得**の判定ロジックを通し、要件通りの通知内容（タイトル / Kindle価格 / 割引率 or ポイント還元率 / Amazonリンク）を Discord へ送る。
取得（スクレイピング）はまだダミー（フィクスチャ）だが、判定と通知は本番品質にする。

## スコープ

### 含む
- `src/types.ts`：商品・通知オブジェクトの型定義（`any` を排除）。
- `src/judge.ts`：判定ロジック（純粋関数）＋ Vitest 単体テスト。
- `src/notify.ts`：Embed 形式での通知内容整形＋送信。
- `fixtures/wishlist.json`：判定・整形の入力となる静的サンプルデータ。
- `src/main.ts`：フィクスチャ読込 → 判定 → 通知 の流れに差し替え。

### 含まない
- 実ブラウザでのデータ取得（→ 増分3）
- 5件ごとの分割送信・レートリミット対応の作り込み（→ 増分5。この回は単純送信でよい）

## 実装内容

1. `src/types.ts`：
   - `WishlistItem`（タイトル, Amazon URL, 基準価格 `P_base`, Kindle価格 `P_kindle`, 付与ポイント `Pt`, フォーマット種別など）
   - `Deal`（通知対象。割引率・ポイント還元率を含む）
2. `src/judge.ts`：要件 §2.3 の判定式を実装。
   - 割引率 `(P_base - P_kindle) / P_base`
   - ポイント還元率 `Pt / P_base`
   - **いずれかが 0.20 以上**なら通知対象（`Deal`）として返す純粋関数。
   - Kindle でない商品・価格欠損データは判定対象外として除外。
3. `src/judge.test.ts`（Vitest）：
   - 割引のみ20%以上 → ヒット
   - ポイントのみ20%以上 → ヒット
   - 両方合算では20%超だが各々は20%未満 → **ヒットしない**
4. `src/notify.ts`：`Deal` を Discord Embed（タイトル / 現在のKindle価格 / 割引率 or ポイント還元率 / Amazonリンク）へ整形して送信。
5. `fixtures/wishlist.json`：上記テストケースを含む現実的なサンプル。
6. `src/main.ts`：フィクスチャ → `judge` → `notify` の縦切りに更新。

## 完了条件（DoD 対応）

- [ ] 「割引のみ」「ポイントのみ」「合算だが各々20%未満」のダミーデータで、要件通りの条件でのみトリガーされる（**DoD 4.1 判定ロジックの正確性**）。
- [ ] スクレイピングデータ・通知オブジェクトに型定義が適用され `any` を極力排除（**DoD 4.3 型安全性**）。
- [ ] 通知に「タイトル / Kindle価格 / 割引率 or ポイント還元率 / Amazonリンク」が含まれる（**要件 §2.4 通知内容**）。
- [ ] `pnpm test` が通る。

## 検証方法

1. `pnpm test` で `judge` の3ケースが期待通り（合算ケースが非ヒット）であることを確認。
2. `pnpm start` を実行し、フィクスチャ内のヒット商品が整形済み Embed で Discord に届くことを確認。
