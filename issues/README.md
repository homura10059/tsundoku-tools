# 実装ロードマップ：Amazon Kindle ウィッシュリスト監視システム

`docs/requirement.md` の要件を、**アジャイルにインクリメンタル**な開発計画へ分解したもの。

## 基本方針：ウォーキングスケルトン（縦切りスライス）

機能（モジュール）単位ではなく、各増分が「**データ取得 → 判定 → 通知**」のパイプライン全体を貫く**縦切りの動作する成果物**になるように分割している。

- 最初の増分で最も薄い経路を End-to-End で動かす。
- 以降の増分で、各次元（取得・判定・通知・運用）を本物に置き換え／強化していく。
- **常に `pnpm start` で動く成果物が手元にある状態**を維持する。

## 技術スタック

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript (Node.js) | 要件 §3 |
| ブラウザ自動操作 | Playwright | 要件 §3 |
| テスト | Vitest | 軽量・TS ネイティブ |
| Lint/Format | Biome | リスタート前リポジトリの慣習を踏襲 |
| パッケージ管理 | **pnpm** | 高速・厳格な依存解決。`pnpm install --frozen-lockfile` で再現性担保 |
| 構成 | 単一パッケージ | 要件が単一ツールへ簡素化されたため |
| 永続化（増分7〜） | **Cloudflare D1** | 設定と観測ログの置き場。実行部は Playwright のため Node のまま残し、D1 へは REST API でアクセスする |

## 進め方

1. 上から順に 1 つずつ実装する。各増分は独立してマージ可能。
2. 各増分の完了条件（DoD 対応）と検証方法を満たしてから次へ進む。
3. 完了したら本 README のチェックや該当 issue を更新する。
