# 増分4: 全件ロードと堅牢性

## 目的

クローラーを「初期表示分のみ」から**全件取得**へ強化し、実運用に耐える堅牢性を持たせる。
無限スクロールで全商品をロードし、Bot 検知回避のジッターを入れ、個別商品のパース失敗でもクラッシュせず処理を継続できるようにする。

## スコープ

### 含む
- 無限スクロール対応：全商品（最大100件程度を想定）がロードされるまで最下部スクロールをシミュレート。
- ジッター：ページ遷移・データ処理の間に **1.0〜3.0秒のランダム待機**を挿入。
- 商品単位のエラーハンドリング：Kindle 以外（紙のみ・ガジェット等）混在や個別パース失敗時に、エラーをログ出力して次の商品へ継続。

### 含まない
- 通知の分割送信（→ 増分5）
- CI / 定期実行（→ 増分6）

## 実装内容

1. `src/crawler.ts` に無限スクロールロジックを追加：
   - スクロール → 新規アイテムのロード待ち → 件数が増えなくなるまで反復。
   - 反復回数・タイムアウトの安全上限を設ける。
2. ジッターユーティリティ（例 `src/util/jitter.ts`）：`sleep(random(1000, 3000))`。スクロール間・処理間で利用。
3. パースを商品単位で `try/catch` し、失敗時はその商品をスキップしてエラーログを出力（全体は継続）。Kindle 以外は対象外として静かに除外。

## 完了条件（DoD 対応）

- [ ] 100件以上登録された公開リストで、無限スクロールが最後まで作動し全件を取りこぼさずパースできる（**DoD 4.1 全件ロードの検証**）。
- [ ] Kindle 以外の形式が混在、または特定アイテムのパースに失敗しても、クラッシュせずエラーをログ出力して次の商品処理を継続する（**DoD 4.2 エラーハンドリング**）。
- [ ] ページ遷移・処理間に 1.0〜3.0 秒のランダム待機が入る（**要件 §2.2 ジッター**）。

## 検証方法

1. 100件以上の公開ウィッシュリストを `WISHLIST_URL` に設定し、`npm run start` で取得件数がリスト総数と一致することを確認。
2. 紙のみ・ガジェット等を含むリストでも最後まで完走し、スキップした商品のエラーログが出ることを確認。
3. ログのタイムスタンプ等からジッターが効いていることを確認。
