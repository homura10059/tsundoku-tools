# 増分5: Discord バッファリング（分割送信）

## 目的

通知層を実運用品質へ強化する。ヒット商品が多数になっても Discord の文字数制限（1メッセージ2,000文字）とレートリミット（429）を回避できるよう、**5件ごとに1メッセージへ集約して分割送信**し、送信間にウェイトを挟む。

## スコープ

### 含む
- `src/notify.ts` の送信ロジックを分割送信へ拡張：
  - ヒット商品を 5 件ごとにチャンク化し、1 チャンク = 1 メッセージ（複数 Embed）として送信。
  - 分割送信の間に**最低2秒**のウェイトを挟む。
- ステートレス運用：通知履歴（DB 等）を保持しない。セール継続中は毎日同じ商品が通知されてよい旨をコード/README に明記。

### 含まない
- 取得・判定ロジックの変更（増分2〜4で確立済み）
- CI / 定期実行（→ 増分6）

## 実装内容

1. `src/notify.ts`：
   - `chunk(deals, 5)` で 5 件ずつに分割。
   - 各チャンクを Embed 配列として 1 リクエストで送信。
   - チャンク間で `await sleep(2000)`（増分4のジッターユーティリティの固定待機版でも可）。
   - 429 受信時のリトライ（`Retry-After` 尊重）を任意で追加。
2. ステートレスである旨を README / コメントに明記。

## 完了条件（DoD 対応）

- [ ] セール対象品が 11 件以上ヒットした際、5件・5件・1件のように分割され、429 を起こさず全メッセージが届く（**DoD 4.1 バッファリングの検証**）。
- [ ] 分割送信の間に最低2秒のウェイトが入る（**要件 §2.4**）。
- [ ] 通知履歴を保持しない（ステートレス運用、**要件 §2.4**）。

## 検証方法

1. 11 件以上ヒットするフィクスチャ、または実リストで `npm run start` を実行。
2. Discord に 5/5/1 の3メッセージが順次届き、429 エラーが発生しないことを確認。
3. 連続実行しても履歴を参照せず毎回通知されることを確認（ステートレス）。
